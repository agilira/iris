# Changelog - Version 1.2.0

## Release Date
2026-04-12

## Overview
Version 1.2.0 is a security hardening and documentation accuracy release.
It adds the slogprovider subpackage, fixes four security issues found during
a systematic fresh-eyes review, ships five new security_test.go files across
all critical packages, and removes all aspirational code that was never
implemented. The result is a leaner, audit-ready codebase that matches its
documentation exactly.

---

## #New

### slogprovider Subpackage
- **Package**: `github.com/agilira/iris/slogprovider`
- bridges Go standard `log/slog` (Go 1.21+) into the Iris pipeline
- implements both `slog.Handler` and `iris.SyncReader` simultaneously
- slog-based services adopt Iris as transport with zero call-site changes
- internal channel decouples slog's synchronous Handler.Handle() from Iris's
  asynchronous ring buffer

```go
provider := slogprovider.New(slogprovider.Config{ChannelSize: 256})
slog.SetDefault(slog.New(provider))

logger, _ := iris.NewReaderLogger(cfg, []iris.SyncReader{provider})
logger.Start()
defer logger.Close()
```

## #Fixed

### CWE-400: Config.Capacity upper bound missing
- Added `const maxCapacity int64 = 1 << 24` (16M entries) to `config.go`
- `Validate()` now rejects any capacity above this ceiling
- WHY: unbounded capacity allowed OOM allocation through configuration alone
- Tests: `TestConfigValidation/capacity_at_maximum_(valid)` and `capacity_exceeds_maximum`

### CWE-116: JSON encoder field key injection
- Field keys now pass through `quoteString()` before being written to output
- Previously only values were escaped; a malicious key could inject arbitrary
  JSON structure into the output stream
- Tests: `TestJSONEncoder_FieldKeyInjection` in encoder_json_security_test.go

### iris.New() skipping Validate()
- `New()` now calls `c.Validate()` after `buildSmartConfig()` resolves defaults
- WHY: smart-config defaults could produce a configuration that silently bypassed
  all validation checks (e.g. Architecture set to an invalid value)
- Tests: `TestNew_ValidatesConfig` with valid, invalid-level, and oversized-capacity sub-cases

### IsValidLevel bounds too restrictive
- `IsValidLevel` now correctly accepts the full range `Debug(-1)` through `Fatal(5)`
- Previously capped at `Error(2)`, incorrectly rejecting `DPanic`, `Panic`, `Fatal`
  as valid filter levels
- Exposed by the New()-validates-config fix (tests using Fatal as filter level broke)
- Tests: `TestIsValidLevel` updated

### test_helpers.go in production binary
- Renamed to `test_helpers_test.go` — excluded from compiled output
- Functions renamed from `TestConfig*` to `makeTestConfig*` variants to avoid
  confusion with Go's test runner naming convention

## #Removed

The following packages and files were aspirational specifications: they described
planned features but contained no working implementation. Removing them eliminates
misleading API surface for consumers of the library.

### otel/ sub-module
- Planned OpenTelemetry integration (never implemented)
- Removed: `otel/otel.go`, `otel/otel_example_test.go`, `otel/integration_test.go`,
  `otel/go.mod`, `otel/go.sum`

### lethebridge/ package
- Planned Lethe ring-buffer bridge (never implemented)
- Removed: `lethebridge/lethebridge.go`

### magic.go
- Magic API layer superseded by Smart API in `iris.go`
- Removed: `magic.go`, `magic_test.go`

### config_loader.go (hot-reload)
- Multi-source config loader with hot-reload — never working
- Removed: `config_loader.go`, `config_loader_multisource_test.go`,
  `config_loader_test.go`, `dynamic_config_test.go`

### integration_test.go
- Integration tests targeting the above aspirational features
- Removed: `integration_test.go`

### examples/ directory
- Examples written for non-existent features
- Removed entirely (autoscaling, config_loader, hot_reload, context, sampler examples)

### Aspirational documentation
- `docs/OPENTELEMETRY.md`         — no code exists
- `docs/HOT_RELOAD.md`            — no code exists
- `docs/LOKI_INTEGRATION.md`      — no code, no writer implementation
- `docs/CONFIGURATION_LOADING.md` — no code
- `AUDIT_ENTERPRISE_TELEMETRY.md` — aspirational enterprise doc
