====================

FEATURES
--------

1. Config.OnDrop: forensic callback for real-time drop detection (CWE-778)

   A new optional field `OnDrop func(totalDropped int64)` in Config provides
   real-time notification when log entries are dropped due to ring buffer
   saturation. The callback runs in the consumer goroutine after each
   processed record, adding zero overhead to the producer fast path.

   Threat model: a burst of drops can signal a log-flooding attack attempting
   to mask malicious activity. Wiring OnDrop to a tamper-evident audit trail
   (e.g. a hash-chained event store) makes the attack itself unforgeable.

   Key properties:
   - Consumer-side only: zero impact on producer throughput (~1ns Load check)
   - Detection latency equals one batch interval (~microseconds under load)
   - Panic-safe: a panicking OnDrop is recovered via safeOnDrop() and
     reported through ErrorHandler (or stderr if nil) — same blast-radius
     containment design as safeInvokeHook()
   - totalDropped is the lifetime monotonically increasing counter
   - Nil OnDrop is safe and incurs no cost (nil check before Load)

   Files: config.go, iris.go
   Tests: ondrop_test.go (6 tests, all pass -race)
   Docs:  README.md, doc.go, docs/BACKPRESSURE_POLICIES.md,
          docs/SECURE_BY_DESIGN.md

BUGFIXES
--------

2. buildSmartConfig: explicit Config fields were silently ignored

   buildSmartConfig overwrote caller-provided values with smart defaults
   for three fields that had no override check:

     - BatchSize: user-set value was discarded; smart default (32) was used
       regardless. A caller with Capacity=8, BatchSize=2 would receive an
       "batch size cannot exceed capacity" error even though the config was
       valid. Found via OnDrop test authoring.

     - TimeFn: a user-supplied custom clock (common in tests) was discarded,
       causing all log records to use CachedTime instead of the injected
       clock.

     - OnDrop: the new callback was not propagated (discovered during
       implementation of this very release).

   Fix: three explicit override checks added to buildSmartConfig following
   the existing pattern for Output, Encoder, Capacity, etc.

   Files: iris.go
   Tests: smartconfig_override_test.go (3 regression tests, all pass -race)
